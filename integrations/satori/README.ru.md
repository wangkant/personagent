# Коннектор Satori

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Português (Brasil)](README.pt-BR.md) · Русский


Этот коннектор связывает [personagent](https://github.com/wangkant/personagent) с сервером [Satori](https://satori.chat). Satori — кроссплатформенный протокол чатов. Сервер вроде [Koishi](https://koishi.chat) (с плагином `server-satori`), Chronocat или LLOneBot входит на платформы чатов, а такой клиент получает каждое сообщение каждого входа через один websocket. Поэтому один процесс коннектора размещает персону на всех платформах, для которых у сервера есть адаптер.

Satori и Koishi — сторонние программы. personagent не нуждается в них для QQ, WeChat, Telegram или Discord, которые подключает сам, и для платформ, которые его локальная страница настраивает через AstrBot. Используйте этот коннектор, если у вас уже работает Koishi или вам нужна платформа, доступная только через Koishi.

Коннектор пересылает каждое разрешённое сообщение в `POST /v1/events` агента как нейтральное событие ([docs/connectors.md](../../docs/connectors.ru.md)) и отправляет ответы обратно через Satori. Он также забирает исходящую очередь агента, так что запланированные реплики, уточняющие вопросы и отговорки доходят до чата.

[satori-python](https://github.com/RF-Tar-Railt/satori-python) берёт на себя сторону Satori: websocket, список входов и HTTP API. Этот коннектор переводит между Satori и форматом событий personagent и использует [`integrations/sdk/personagent_connector.py`](../sdk/personagent_connector.py) для подписи и цикла исходящей очереди.

## Настройка с Koishi

1. **Koishi.** Установите Koishi через настольный лаунчер или `npm init koishi@latest`. В его консоли добавьте и настройте адаптер своей платформы, например `adapter-telegram` или `adapter-discord`, и убедитесь, что бот в сети. Включите плагины `server` и `server-satori`. Тогда Koishi обслуживает Satori по адресу `http://127.0.0.1:5140/satori`. Задайте `server-satori` параметр `token`, если этот порт доступен не только с этой машины.

   Koishi продолжает выполнять другие плагины. Если какой-то из них тоже отвечает на сообщения, например чат-модель или плагин ответов, он будет отвечать вместе с персоной, и коннектор не может заставить его замолчать. Отключите этот плагин или исключите из него пересылаемые разговоры.

2. **Агент.** Запустите personagent (`personagent run`, см. его README). Если коннектор и агент на разных хостах, задайте `CONNECTOR_TOKEN` в `.env` агента и поставьте агента за HTTPS. Задайте токен до добавления прокси или туннеля, даже на одном хосте.

3. **Коннектор.** Коннектор — это скрипт в этом репозитории, поэтому ему нужна копия репозитория (клон или ZIP с GitHub) и своё окружение Python, потому что `satori-python` не входит в зависимости personagent. В клоне, где уже есть `.venv` personagent, установите в это окружение:

   ```bash
   .venv/bin/python -m pip install -r integrations/satori/requirements.txt
   ```

   Если вы установили personagent с PyPI через pip или запускаете через uvx, создайте отдельное venv рядом с копией:

   ```bash
   python -m venv connector-venv
   connector-venv/bin/python -m pip install -r integrations/satori/requirements.txt
   ```

   В Windows интерпретатор — `.venv\Scripts\python.exe` или `connector-venv\Scripts\python.exe`. Затем скопируйте файл настроек:

   ```bash
   cp integrations/satori/.env.example integrations/satori/.env
   ```

   В `integrations/satori/.env` задайте URL и токен сервера Satori, базовый URL и `CONNECTOR_TOKEN` агента и пересылаемые разговоры (см. [Списки разрешённых](#списки-разрешённых)). Затем запустите коннектор тем же интерпретатором:

   ```bash
   .venv/bin/python integrations/satori/satori_connector.py
   ```

   `--config FILE` читает другой файл настроек. Любую настройку можно также задать переменной окружения, которая важнее файла.

4. **Проверьте работу.** Для каждого бота сервера журнал показывает строку вроде `Satori login telegram:7000 is ONLINE`. Упомяните бота в пересылаемой группе. Журнал агента покажет ход, а ответ появится в чате. Если ничего не происходит, задайте `SATORI_LOG_LEVEL=DEBUG`.

## Настройки

| Настройка | По умолчанию | Значение |
|---|---|---|
| `SATORI_URL` | `http://127.0.0.1:5140/satori` | Сервер Satori. `/v1` в конце необязателен. |
| `SATORI_TOKEN` | | Токен сервера (в Koishi `server-satori` → `token`). |
| `PERSONAGENT_URL` | `http://127.0.0.1:8080` | Базовый URL агента. Добавляются `/v1/events` и `/v1/outbox`. |
| `CONNECTOR_TOKEN` | | `CONNECTOR_TOKEN` агента. |
| `SATORI_GROUPS` | | Пересылаемые группы, как идентификаторы каналов или серверов, можно `platform:id`. Пусто — ничего не пересылается, `*` — все. |
| `SATORI_DM_USERS` | | Люди, чьи личные сообщения пересылаются, как идентификаторы пользователей, можно `platform:id`. Пусто — ничего не пересылается, `*` — все. |
| `SATORI_PLATFORMS` | все | Ограничивает коннектор этими платформами Satori. |
| `SATORI_PLATFORM_NAMES` | `qq=qqbot` | Переименовывает платформы так, как их видит агент: `satori_name=name, ...` |
| `SATORI_OUTBOX_ENABLED` | `true` | Забирать исходящую очередь агента. |
| `SATORI_CONNECTOR_ID` | из `SATORI_URL` | Идентификатор этого коннектора у агента. Не меняйте его. |
| `SATORI_TIMEOUT_S` | `420` | Сколько может длиться один ход. Держите выше 3 × `LLM_TIMEOUT_S` агента. |
| `SATORI_INLINE_IMAGES_ENABLED` | `false` | Скачивать публичные URL изображений в коннекторе вместо передачи URL агенту. |
| `SATORI_LOG_LEVEL` | `INFO` | |

URL агента должен быть адресом loopback или HTTPS с заданным `CONNECTOR_TOKEN`. Иначе коннектор отказывается запускаться. Если `SATORI_TOKEN` будет отправлен по незашифрованному `http` на другой хост, коннектор пишет предупреждение в журнал.

## Списки разрешённых

По умолчанию коннектор запрещает всё. С пустыми списками он ничего не пересылает.

- Группа — это канал Satori. Она пересылается, когда идентификатор её канала или сервера есть в `SATORI_GROUPS`. Поэтому в Discord или KOOK один идентификатор сервера допускает все каналы этого сервера, а каждый канал остаётся отдельным разговором.
- Личное сообщение пересылается, когда идентификатор отправителя есть в `SATORI_DM_USERS`.
- Запись может называть свою платформу, как `telegram:-1001234` или `discord:4242`, и тогда совпадает только на ней. Запись без платформы совпадает на всех.
- `*` пересылает все группы (или все личные сообщения) и помечает событие `prefiltered: false`. Тогда решают `ACCESS_GROUPS` и `ACCESS_DM_USERS` самого агента, а платформа без записей там отклоняется.

Плагин `inspect` в Koishi печатает идентификаторы платформы, канала, сервера и пользователя сообщения.

## Имена платформ и QQ

personagent хранит идентификаторы как `<platform>:<id>`, где платформа — это платформа входа Satori (`telegram`, `discord`, `onebot` и так далее). Её показывает строка журнала из шага 4. Особых случаев два:

- **QQ через OneBot** (`adapter-onebot` в Koishi, за ним NapCat или LLOneBot) использует номера QQ как идентификаторы. Чтобы сохранить то, чему агент научился на существующем развёртывании QQ, добавьте платформу в `CONNECTOR_QQ_PLATFORMS` агента (`CONNECTOR_QQ_PLATFORMS=onebot`). Тогда её идентификаторы хранятся без префикса, как номера QQ из NapCat, и к ним применяются записи QQ из `ACCESS_GROUPS` и `ACCESS_DM_USERS`. Делайте так только для платформы, чьи идентификаторы действительно номера QQ.
- **Официальный API ботов QQ** (`adapter-qq` в Koishi) называет свою платформу `qq`, но её идентификаторы — это openid, а не номера QQ. Коннектор переименовывает платформу в `qqbot`. `SATORI_PLATFORM_NAMES` заменяет это переименование. personagent может также сам подключать официальных ботов QQ, без Koishi.

## Что работает

| Функция | Состояние |
|---|---|
| Групповые чаты и личные сообщения | Да. Личное сообщение — это канал `DIRECT` или сообщение без сервера. |
| Определение обращения (`addressed`) | `<at>` бота (по идентификатору или по имени бота, если сервер не даёт идентификатор) и ответ на сообщение бота. `@all` считается текстом, а не упоминанием. |
| Цитируемые сообщения | Цитируемый текст, отправитель и идентификатор из элемента `<quote>` или из `message.quote`. |
| Входящие изображения | Изображения `data:` и `internal:` и изображения на сервере Satori встраиваются. Публичные URL передаются, чтобы агент их получил сам. URL частных сетей описываются как `(sent an image)`. Не больше 4 загрузок на сообщение, по 4 МБ каждая. |
| Стикеры и эмодзи | `<emoji>` и `<face>` из QQ приходят как эмодзи, и персона знает, что не может их видеть. |
| Голос, видео, файлы | Описываются словами: `(sent a voice message)`, `(sent a video)`, `(sent a file: deck.pdf)`. |
| Ответы | Текст и изображения как URI `data:`, каждый отправляется отдельным сообщением с небольшой паузой. В группах упоминание, которое просит агент, становится `<at>`. |
| Платформы с пассивным ответом | Ответы несут `referrer` события, который нужен официальному API ботов QQ, чтобы ответить на сообщение. |
| Исходящая очередь | Запланированные реплики, уточнения и отговорки идут в канал через вход, получивший разговор. Коннектор подписывает каждый дескриптор ответа ключом, выведенным из `SATORI_TOKEN` и `CONNECTOR_TOKEN`, и отправляет только на подписанные им дескрипторы. После смены любого из токенов разговор снова становится доступен, когда пришлёт сообщение. Агент с `CONNECTOR_OUTBOX_ENABLED=false` отвечает 404, и коннектор повторяет попытку каждые 10 минут. |
| Индикатор набора | Нет. В Satori нет API набора. |
| `owned` | Соблюдается: коннектор больше ничего не отправляет. Другие плагины Koishi он остановить не может (см. шаг 1). |

Правила платформ по-прежнему действуют. Например, официальный API ботов QQ строго ограничивает сообщения, которые бот может отправлять сам, поэтому доставка из исходящей очереди там может вернуться как `failed`.
