# Коннектор Matrix

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Português (Brasil)](README.pt-BR.md) · Русский


Этот коннектор размещает [personagent](https://github.com/wangkant/personagent) в комнатах Matrix, а через [мосты mautrix](https://docs.mau.fi/bridges/) — в WhatsApp, Signal, Messenger, Instagram, Google Messages и других сетях. Мосты — сторонние программы, которые вы запускаете сами на домашнем сервере под вашим управлением. personagent не нуждается в них для платформ, которые подключает со своей локальной страницы.

personagent также подключается к Matrix сам, без этого коннектора: раздел «Подключение платформ» на его локальной странице или команда `personagent connect matrix` запрашивает адрес домашнего сервера, токен доступа учётной записи бота и ваш собственный Matrix ID. Это встроенное подключение читает только комнаты без сквозного шифрования и входит только в те комнаты, в которые вы приглашаете бота с этого Matrix ID. Используйте вместо него этот коннектор, если бот должен читать зашифрованные комнаты, отвечать в порталах мостов или в комнатах, куда его приглашают другие люди, либо если вы хотите выбирать комнаты и людей по спискам разрешённых.

Коннектор — это небольшой самостоятельный процесс на основе [matrix-nio](https://github.com/matrix-nio/matrix-nio), поддерживающего сквозное шифрование без libolm. Он входит на домашний сервер как обычный пользователь Matrix, пересылает каждое разрешённое сообщение комнаты в `POST /v1/events` агента как событие, не зависящее от платформы ([docs/connectors.md](../../docs/connectors.ru.md)), и публикует ответы агента в комнате. Он также опрашивает исходящую очередь агента, так что запланированные реплики, уточняющие вопросы и резервные ответы тоже доходят до Matrix.

## Что он делает

На входе, для каждого сообщения в разрешённой комнате:

- Событие использует платформу `matrix` и исходные идентификаторы Matrix, поэтому агент хранит `matrix:@alex:example.org` и `matrix:!room:example.org`.
- Комната считается личным чатом, если её перечисляет `m.direct` бота или если в ней ровно один участник помимо бота и пользователей из `MATRIX_IGNORE_USERS`. Личный чат определяется человеком, группа — комнатой. Комната, названная по идентификатору в `MATRIX_GROUPS`, всегда группа.
- `addressed` истинно, когда сообщение упоминает бота или отвечает на одно из его сообщений. Упоминание — это `m.mentions` или, от клиентов, слишком старых для `m.mentions`, плашка либо идентификатор бота в тексте.
- Ответ несёт отправителя и текст цитируемого сообщения. Коннектор берёт их из кэша недавних событий или получает родительское событие. Он убирает резервный текст ответа, который добавляют старые клиенты (`> <@alex:example.org> ...`), поэтому агент никогда не прочитает чужие слова как слова отправителя.
- Изображения и стикеры до 4 МБ скачиваются, расшифровываются в зашифрованных комнатах и отправляются агенту как байты. Голосовые сообщения, видео и файлы описываются словами.
- Сообщения комнаты доходят до агента в порядке отправки. Сообщение, отправленное после изображения, ждёт, пока изображение скачается. При этом агент может работать над несколькими ходами сразу.
- Метка времени — это `origin_server_ts` домашнего сервера.
- Коннектор пропускает собственные сообщения бота, сообщения `m.notice` (тип, который отправляют боты), правки, реакции, сообщения от `MATRIX_IGNORE_USERS`, накопившиеся сообщения, которые возвращает первая синхронизация при запуске, и всё старше `MATRIX_MAX_EVENT_AGE_S`, например историю, которую мост загружает в новую комнату.

На выходе:

- Текстовые ответы — это `m.text`. Когда агент просит упомянуть кого-то в группе, ответ начинается с плашки и перечисляет этого человека в `m.mentions`. Все остальные ответы несут пустой `m.mentions`, поэтому ни один клиент не превратит имя в тексте в уведомление.
- Ответы с изображениями загружаются, а в зашифрованных комнатах шифруются.
- Пока агент работает над ходом, показывается уведомление о наборе.
- На сообщение в ветке отвечают в этой ветке.
- Когда агент берёт разговор на себя, бот помечает сообщение прочитанным (`MATRIX_READ_RECEIPTS_ENABLED`). Через мост это видно как отметка о прочтении в другой сети.
- Доставка из исходящей очереди идёт в комнату, откуда разговор пришёл последним. `reply_handle` события — это идентификатор комнаты.

## Установка

Нужны работающий personagent и учётная запись Matrix для бота. Создайте отдельную учётную запись, а не используйте совместно учётную запись человека.

Коннектор — это скрипт в этом репозитории, поэтому ему нужна копия репозитория (клон или ZIP с GitHub) и своё окружение Python, потому что `matrix-nio` не входит в зависимости personagent. В клоне, где уже есть `.venv` personagent, установите в это окружение:

```bash
.venv/bin/python -m pip install -r integrations/matrix/requirements.txt
```

Если вы установили personagent с PyPI через pip или запускаете через uvx, создайте отдельное виртуальное окружение рядом с копией:

```bash
python -m venv connector-venv
connector-venv/bin/python -m pip install -r integrations/matrix/requirements.txt
```

В Windows интерпретатор — `.venv\Scripts\python.exe` или `connector-venv\Scripts\python.exe`. Затем скопируйте файл настроек:

```bash
cp integrations/matrix/.env.example integrations/matrix/.env
```

Отредактируйте `integrations/matrix/.env`:

```ini
MATRIX_URL=https://matrix.example.org
MATRIX_USER_ID=@nova:example.org
MATRIX_PASSWORD=...
MATRIX_GROUPS=!AbCdEf:example.org
MATRIX_DM_USERS=@alex:example.org
PERSONAGENT_URL=http://127.0.0.1:8080
```

Затем запустите коннектор рядом с агентом, тем же интерпретатором:

```bash
.venv/bin/python integrations/matrix/matrix_connector.py
# or: .venv/bin/python integrations/matrix/matrix_connector.py --config /path/to/matrix.env
```

Пригласите бота в комнату из `MATRIX_GROUPS`, и он присоединится. В Element идентификатор комнаты находится в настройках комнаты, в разделе «Дополнительно».

### Вход

Вход по паролю — самый простой способ начать. Коннектор сохраняет полученный сеанс (идентификатор пользователя, идентификатор устройства и токен доступа) в `MATRIX_STORE_DIR/session.json` и использует его при следующем запуске, поэтому перезапуск не создаёт новое устройство. Удалите этот файл, чтобы войти заново.

Чтобы использовать существующий токен доступа, задайте `MATRIX_ACCESS_TOKEN`. Коннектор запрашивает у домашнего сервера, какой учётной записи принадлежит токен. Не используйте токен сеанса, которым пользуетесь сами, потому что выход из неё также отключает бота.

Когда домашний сервер отключает бота (`M_UNKNOWN_TOKEN`), коннектор останавливается с ошибкой, сообщающей об этом. После входа по паролю повторный запуск выполнит вход снова. С `MATRIX_ACCESS_TOKEN` сначала задайте новый токен. Любая другая неудачная синхронизация повторяется с задержкой, которая удваивается до одной минуты.

### Где может работать агент

Это правило задано протоколом. `PERSONAGENT_URL` должен быть адресом loopback или HTTPS с `CONNECTOR_TOKEN`, равным `CONNECTOR_TOKEN` агента. Иначе коннектор отказывается запускаться. Задайте токен с обеих сторон до того, как разместите прокси или туннель перед агентом, даже на одном хосте.

## Настройки

[.env.example](.env.example) перечисляет все настройки. Списки разделяются запятыми и принимают шаблоны, поэтому `@*:example.org` подходит ко всему серверу. Пустой список никому не отвечает. Одиночная `*` подходит ко всем и помечает событие `prefiltered: false`. В этом случае решение принимают только `ACCESS_GROUPS` / `ACCESS_DM_USERS` самого агента, а платформа без записей там отклоняется.

| Настройка | Значение |
|---|---|
| `MATRIX_GROUPS` | Групповые комнаты для ответов, по идентификатору комнаты. `*` означает все комнаты, куда вошёл бот. |
| `MATRIX_DM_USERS` | Люди, которые могут общаться с ботом в личном чате. `*` означает всех. |
| `MATRIX_INVITE_FROM` | Пользователи, чьи приглашения принимает бот. Приглашения в комнаты из `MATRIX_GROUPS` и приглашения в личный чат от `MATRIX_DM_USERS` принимаются всегда. Остальные остаются без ответа. |
| `MATRIX_IGNORE_USERS` | Никогда не получают ответа и не считаются участниками, когда коннектор отличает личный чат от группы. |
| `MATRIX_E2EE_ENABLED` | Сквозное шифрование. См. ниже. |
| `MATRIX_TIMEOUT_S` | Сколько может длиться один ход. Значение должно превышать 3 × `LLM_TIMEOUT_S` агента. |
| `MATRIX_OUTBOX_ENABLED` | Опрашивать исходящую очередь агента. |

## Мосты: WhatsApp, Signal, Messenger, Instagram и другие

Мост mautrix входит в другую сеть от имени её учётной записи и отражает её чаты в комнаты Matrix, называемые порталами. Все участники на той стороне появляются в Matrix как призрачные пользователи вроде `@whatsapp_4912345:example.org`. Когда в мост вошла именно учётная запись Matrix бота, персона присутствует в этой сети. Контакт WhatsApp пишет на номер персоны, мост публикует сообщение в комнате портала, этот коннектор пересылает его, и ответ идёт обратно тем же путём.

| Сеть | Мост |
|---|---|
| WhatsApp | [mautrix-whatsapp](https://github.com/mautrix/whatsapp) |
| Signal | [mautrix-signal](https://github.com/mautrix/signal) |
| Facebook Messenger, личные сообщения Instagram | [mautrix-meta](https://github.com/mautrix/meta) |
| Google Messages (RCS и SMS через телефон Android) | [mautrix-gmessages](https://github.com/mautrix/gmessages) |
| Google Voice, LinkedIn, личные сообщения Twitter/X и Bluesky, Google Chat, iMessage | Другие [мосты mautrix](https://github.com/mautrix) |
| Telegram, Discord, Slack, Zulip, IRC | Мосты существуют, но к этим сетям можно подключиться и без них. personagent сам подключает Telegram, Discord, Zulip и IRC, а Slack — через AstrBot, который запускает его локальная страница. |

Как настроить:

1. Запустите домашний сервер под своим контролем (Synapse или другой сервер с поддержкой сервисов приложений) и установите мост по [его документации](https://docs.mau.fi/bridges/). Дайте учётной записи бота уровень доступа `user` в `permissions` моста.
2. Войдите в Element как бот, откройте чат с ботом моста (например, `@whatsappbot:example.org`) и отправьте `login`. Свяжите учётную запись в сети, которую будет использовать персона. Для WhatsApp, Signal и Google Messages отсканируйте QR-код телефоном персоны. Для Messenger и Instagram укажите вход Meta. См. [Использование мостов](https://docs.mau.fi/bridges/general/using-bridges.html).
3. Позвольте коннектору войти в порталы и исключите собственные сообщения моста:

   ```ini
   MATRIX_INVITE_FROM=@whatsappbot:example.org
   MATRIX_IGNORE_USERS=@whatsappbot:example.org,@whatsapp_4900000000:example.org
   MATRIX_DM_USERS=@whatsapp_*:example.org
   MATRIX_GROUPS=!groupPortal:example.org
   ```

   Вторая запись в `MATRIX_IGNORE_USERS` — это призрак моста для собственного номера персоны. Без [двойного управления](https://docs.mau.fi/bridges/general/double-puppeting.html) сообщение, набранное на телефоне персоны, приходит в Matrix от этого призрака, и бот ответил бы сам себе. `MATRIX_GROUPS=*` пересылает все групповые порталы, где есть бот, и тогда personagent отвечает только в комнатах, которые его `ACCESS_GROUPS` перечисляет как `matrix:!room:server`. Перечислите здесь идентификаторы комнат, чтобы выбирать комнаты в коннекторе.

### Использование учётной записи

- Мост — неофициальный клиент сети, вошедший от имени обычной пользовательской учётной записи (связанное устройство или веб-сеанс). Он не использует API ботов, и ничто в сети не помечает эту учётную запись как бота.
- Персоне нужна своя учётная запись, обычно со своим номером телефона, и телефон должен оставаться доступным. WhatsApp отключает связанные устройства, когда телефон не в сети около двух недель, а Google Messages работает, только пока телефон Android в сети.
- В групповых чатах учётная запись персоны выглядит как любой другой участник. Сообщите людям, что они общаются с ботом.
- Реакции, правки, удаления, опросы и звонки агенту не пересылаются.

### Условия каждой сети

Прочитайте условия каждой сети перед подключением.

- [WhatsApp](https://www.whatsapp.com/legal/terms-of-service) относит автоматическую отправку сообщений к недопустимым коммуникациям, запрещает неразрешённое неличное использование и может блокировать учётные записи, нарушающие эти правила. Одобренный им путь автоматизации — WhatsApp Business Platform, которую мост не использует.
- [Signal](https://signal.org/legal/) также относит автоматическую отправку сообщений к недопустимым.
- [Facebook](https://www.facebook.com/terms.php) и [Instagram](https://help.instagram.com/581066165581870) запрещают автоматизированный доступ без разрешения Meta, и Meta может заблокировать учётную запись, вошедшую с незнакомого клиента.
- Google Messages подпадает под [условия Google](https://policies.google.com/terms) и условия вашего оператора для SMS и RCS, который может брать плату за автоматические сообщения или ограничивать их.

Используйте отдельную учётную запись, потеря которой для вас допустима, только в разговорах, где люди знают, что общаются с ботом, и прочитайте [DISCLAIMER.md](../../docs/DISCLAIMER.ru.md).

## Сквозное шифрование

С `MATRIX_E2EE_ENABLED=false` (по умолчанию) бот читает только незашифрованные комнаты. В зашифрованной комнате он записывает в журнал, что не может расшифровать сообщение, и никогда не отправляет туда ответ открытым текстом.

С `MATRIX_E2EE_ENABLED=true`:

- `MATRIX_STORE_DIR` (по умолчанию `runtime/` рядом со скриптом, git его игнорирует) хранит ключи устройства и токен синхронизации. Сохраняйте эту папку. Если она потеряна, бот становится новым устройством, которое не может прочитать ничего зашифрованного до этого момента.
- Устройство должно оставаться тем же между перезапусками. Вход по паролю сохраняет его через сохранённый сеанс. С токеном доступа задайте `MATRIX_DEVICE_ID` равным устройству токена.
- Бот делится ключами со всеми устройствами комнаты, проверенными или нет. Он не может пройти интерактивную проверку, поэтому люди видят его устройство как непроверенное. Резервной копии ключей и перекрёстной подписи у него нет.
- Сообщение, ключ которого не пришёл, записывается в журнал и пропускается без повтора.
- Мост mautrix может шифровать свои порталы ([шифрование до моста](https://docs.mau.fi/bridges/general/end-to-bridge-encryption.html)). Мост хранит эти ключи на вашем сервере, поэтому защита на этом заканчивается, а другая сеть несёт сообщение под своим шифрованием. Если ваш мост шифрует порталы, включите `MATRIX_E2EE_ENABLED`.
