# Протокол коннекторов

[English](connectors.md) · [简体中文](connectors.zh-CN.md) · [繁體中文](connectors.zh-TW.md) · [日本語](connectors.ja.md) · [한국어](connectors.ko.md) · [Español](connectors.es.md) · [Français](connectors.fr.md) · [Deutsch](connectors.de.md) · [Português (Brasil)](connectors.pt-BR.md) · Русский

Агент никогда не взаимодействует с чат-платформой напрямую. Эту задачу выполняет коннектор. Он входит на одну платформу или во фреймворк, охватывающий многие, превращает каждое входящее сообщение в нейтральное событие, отправляет его в personagent и доставляет то, что вернётся. Всё, что зависит от платформы, остаётся в коннекторе, поэтому агент видит один и тот же формат с любой платформы.

В этом репозитории четыре коннектора:

| Коннектор | Куда подключается | Путь |
|---|---|---|
| Прямой | Официальные боты QQ, личный WeChat (iLink), Telegram, Discord, Matrix, Twitch, IRC, Zulip, VK и Stoat, без других программ. Локальная страница и `personagent up` запускают его одним процессом, `python -m persona_agent.direct`. | `persona_agent/direct/` |
| Плагин AstrBot | Платформы AstrBot, стороннего моста. AstrBot, которым personagent управляет для KOOK, Feishu/Lark, DingTalk, Slack, WeCom, Mattermost, Misskey, OneBot v11 и остальных, получает плагин автоматически. Для уже работающего у вас AstrBot настройку выполняет `personagent connect astrbot`. Можно также загрузить `astrbot_plugin_personagent.zip` из GitHub Release через функцию Install from File в AstrBot и задать `connector_token` самостоятельно. | `integrations/astrbot/` |
| Satori | Все реализации Satori (Koishi и другие, сторонние): QQ, Telegram, Discord, KOOK, Lark, DingTalk, LINE, WhatsApp, Matrix, Zulip, электронная почта и другие. | `integrations/satori/` |
| Matrix | Комнаты Matrix, а через сторонние мосты mautrix — WhatsApp, Signal, Messenger, Instagram, Google Messages и другие. | `integrations/matrix/` |

Помощники для программирования не являются чат-платформами, поэтому для них используется отдельный путь: MCP-сервер `personagent mcp`, описанный в [руководстве пользователя](guide.ru.md#помощники-для-программирования).

Все четыре используют протокол, описанный на этой странице. Чтобы написать новый, нужны эта страница и HTTP-клиент. Помощник на Python в `integrations/sdk/personagent_connector.py` подписывает запросы и запускает цикл исходящей очереди за вас. Он принимает базовый URL, токен и `connector_id` коннектора и требует `httpx`.

## Настройка

Локальная страница настраивает прямой коннектор. Остальные три используют одинаковые имена, так что настройка означает в каждом одно и то же:

| Значение | Satori | Matrix | Ключ плагина AstrBot |
|---|---|---|---|
| Базовый URL personagent, например `http://127.0.0.1:8080`. Коннектор добавляет `/v1/events` и `/v1/outbox`. | `PERSONAGENT_URL` | `PERSONAGENT_URL` | `personagent_url` |
| Общий токен, равный `CONNECTOR_TOKEN` агента | `CONNECTOR_TOKEN` | `CONNECTOR_TOKEN` | `connector_token` |
| Идентификатор этого коннектора (`connector_id` ниже) | `SATORI_CONNECTOR_ID` | `MATRIX_CONNECTOR_ID` | `connector_id` |
| Сколько может длиться один запрос, в секундах | `SATORI_TIMEOUT_S` | `MATRIX_TIMEOUT_S` | `timeout_s` |
| Опрашивать исходящую очередь | `SATORI_OUTBOX_ENABLED` | `MATRIX_OUTBOX_ENABLED` | `outbox_enabled` |
| Группы для пересылки | `SATORI_GROUPS` | `MATRIX_GROUPS` | `groups` |
| Люди, чьи личные сообщения пересылаются | `SATORI_DM_USERS` | `MATRIX_DM_USERS` | `dm_users` |
| Сервер платформы | `SATORI_URL` | `MATRIX_URL` | Собственный у AstrBot |

Пустой список групп или личных сообщений не пересылает ничего этого вида. `*` пересылает всё и помечает события как `"prefiltered": false`, оставляя решение за `ACCESS_GROUPS` и `ACCESS_DM_USERS` агента. Остальные настройки перечислены в README каждого коннектора.

## Адресация

personagent хранит каждый идентификатор как `<platform>:<id>`, например `telegram:-1001234` для группы или `discord:4242` для пользователя. `platform` — имя платформы у коннектора, в нижнем регистре и без `:`.

QQ — единственное исключение, оставленное для совместимости. Его идентификаторы хранятся без префикса (`123456`), а `qq:123456` в любой настройке означает то же самое. Если коннектор работает с QQ и вы хотите согласовать его усвоенное состояние с уже существующим развёртыванием QQ, укажите его платформу в `CONNECTOR_QQ_PLATFORMS`. QQ-адаптер плагина AstrBot называется `aiocqhttp`. Идентификаторы перечисленных там платформ тоже хранятся без префикса.

## Аутентификация

Обе конечные точки ниже используют одну схему. Когда у агента задан `CONNECTOR_TOKEN`, каждый запрос несёт четыре заголовка:

- `X-Personagent-Token`: токен.
- `X-Personagent-Timestamp`: секунды unix. Значение, отличающееся от часов агента более чем на пять минут, отклоняется.
- `X-Personagent-Nonce`: новое случайное значение. Повторно использованный nonce отклоняется.
- `X-Personagent-Signature`: `sha256=`, а за ним шестнадцатеричный HMAC-SHA256 от `timestamp + "." + nonce + "." + body` с токеном в качестве ключа.

Тело — канонический JSON: UTF-8, отсортированные ключи, компактные разделители и неэкранированный не-ASCII. Токен также служит ключом подписи, поэтому не допускайте его попадания в журналы.

Без токена агент принимает только локальные программы, напрямую обращающиеся к `127.0.0.1` или `localhost`. Коннектор обязан отказываться отправлять куда-либо, кроме loopback-URL или HTTPS-URL с токеном.

## Входящие: `POST /v1/events`

Каждый запрос передаёт одно сообщение и возвращает ответы на него.

```json
{
  "platform": "telegram",
  "conversation_type": "group",
  "conversation_id": "-1001234",
  "sender_id": "42",
  "sender_name": "Alex",
  "bot_id": "7000",
  "message_id": "881",
  "sent_at": 1790320000,
  "addressed": true,
  "text": "Nova, how was your day?",
  "segments": [
    {"type": "text", "text": "Nova, how was your day?"}
  ],
  "connector_id": "astrbot-7f3c",
  "reply_handle": "tg-bot:GroupMessage:-1001234",
  "capabilities": ["outbox", "quote_text"]
}
```

Обязательные поля: `platform`, `conversation_type` (`group` или `dm`), `sender_id`, `message_id` и `sent_at`, а для групп ещё `conversation_id`. `sent_at` — время, которое платформа поставила сообщению, в секундах unix. Отправляйте исходные идентификаторы платформы. Префикс добавляет агент.

`addressed` задаёт коннектор. Значение истинно, когда сообщение упоминает бота, отвечает на одно из сообщений бота или адресовано боту по правилам самой платформы. Агент и сам замечает своё имя в тексте. Цитату своего сообщения или @ бота он считает реакцией, на которой может учиться, поэтому задавайте `addressed` в ответах боту. Цитата сообщения другого участника никогда не является реакцией на бота.

Событие, в котором `sender_id` равен `bot_id`, — это эхо собственного сообщения бота. Агент отбрасывает его без чтения и отвечает `{"handled": false, "owned": true, "replies": []}`, так что собственная логика бота в коннекторе тоже молчит. Пропускайте такие события в коннекторе.

Сегменты идут по порядку:

| Тип | Поля | Примечания |
|---|---|---|
| `text` | `text` | |
| `mention` | `user_id`, `name` | Упоминание кого-либо. Это упоминание бота, когда `user_id` равен `bot_id`. |
| `image` | `url` или `b64`, `sticker` (логическое значение) | `sticker` отмечает стикер, отправленный как изображение. |
| `emoji` | `name`, `id` | Стикер платформы или пользовательский эмодзи, которых агент не видит. `name` — то, как его назвал бы человек. |
| `reply` | `message_id`, `text`, `sender_id`, `sender_name` | Сообщение, которое цитирует это. Отправляйте `text` всякий раз, когда платформа его предоставляет. |

Всё остальное описывайте словами, сегментом `text` вроде `(sent a voice message)` или `(sent a file: deck.pdf)`. Агент отбрасывает неизвестные типы сегментов.

Эти необязательные поля открывают больше возможностей агента:

| Поле | Значение |
|---|---|
| `connector_id` | Стабильный идентификатор этого экземпляра коннектора. Он обязателен для исходящей очереди. |
| `reply_handle` | Всё, что нужно коннектору, чтобы позже обратиться к этому разговору без входящего сообщения: `unified_msg_origin` у AstrBot, идентификатор комнаты Matrix или вход Satori плюс идентификатор канала. Агент считает его непрозрачным, хранит для каждого разговора и возвращает в доставках из исходящей очереди. |
| `capabilities` | Что умеет коннектор. `outbox` означает, что он опрашивает исходящую очередь и может отправлять без запроса. `quote_text` означает, что сегменты ответа содержат цитируемый текст. |
| `prefiltered` | `true` (по умолчанию), когда коннектор применил собственный список разрешённых. `false` делает списки агента единственным фильтром. |
| `proactive` | Помечает событие личного сообщения как подсказку, написанную коннектором, а не слова человека. См. «Заговорить первым без исходящей очереди». |

Ответ выглядит так:

```json
{"handled": true, "owned": true, "replies": [
  {"type": "text", "text": "not bad, rained all afternoon", "mention_user_id": "telegram:42"},
  {"type": "image", "b64": "..."}
]}
```

- `replies`: отправляйте по порядку, каждый отдельным сообщением. Если есть `mention_user_id`, это идентификатор с префиксом, который нужно упомянуть. Показывайте упоминание так, как это делает платформа.
- `owned`: агент взял этот разговор на себя. Когда значение истинно, не давайте другой логике бота отвечать, даже если `replies` пуст, потому что персона решила промолчать. Когда ложно, сообщение обрабатываете вы. Либо разговор не входит в списки разрешённых агента, либо агент вообще не может ответить (нет `LLM_API_KEY` или `AGENT_ENABLED=false`). Во втором случае в журнале агента есть одна строка ERROR с причиной.
- Запрос длится до конца хода: короткий антидребезг плюс время модели. Все вызовы модели за ход, включая повторы, делят один бюджет в 1,5 × `LLM_TIMEOUT_S` как в группе, так и в личных сообщениях, а сообщение, пришедшее, пока предыдущий ход того же разговора ещё обрабатывается, сначала дожидается конца того хода и только потом начинает свой. Отведите минимум 3 × `LLM_TIMEOUT_S` секунд (360 при значении по умолчанию).
- Команда памяти (например, «remember ...»), пришедшая, пока ход её разговора ещё обрабатывается, получает ответ после этого хода. Коннектор, объявивший `outbox`, сразу получает `{"handled": false, "owned": true, "replies": []}`, а результат позже, как доставку `follow_up`. Без `outbox` результат приходит в ответе на запрос: на её собственный или на другой ожидающий запрос того же разговора, поэтому ответ может содержать `replies`, упоминающие не отправителя события, а кого-то другого.

## Исходящая очередь: `POST /v1/outbox`

Некоторые сообщения не отвечают на запрос. Например, запланированное начало разговора, уточняющий вопрос после отказа, ответ на команду памяти, которая ждала окончания хода, и резервный ответ при сбое модели в группе. Агент ставит их в очередь для каждого разговора, а коннектор, объявивший `outbox`, забирает их, поэтому коннектор за NAT или файрволом работает так же. Разговоры, хранящиеся под идентификаторами QQ без префикса (см. «Адресация»), тоже используют исходящую очередь, пока их коннектор её опрашивает. В противном случае они отправляются через HTTP API NapCat, если задан `QQ_ONEBOT_URL`.

Запрос:

```json
{
  "kind": "outbox.pull",
  "connector_id": "astrbot-7f3c",
  "wait_s": 25,
  "max_deliveries": 10,
  "acks": [
    {"delivery_id": "d_5c1f...", "status": "sent", "sent_items": 2}
  ]
}
```

Агент удерживает запрос до `wait_s` секунд (не более 30), пока что-нибудь не окажется в очереди, а затем отвечает:

```json
{
  "deliveries": [
    {
      "delivery_id": "d_9a07...",
      "conversation_key": "telegram:-1001234",
      "reply_handle": "tg-bot:GroupMessage:-1001234",
      "platform": "telegram",
      "conversation_type": "group",
      "conversation_id": "-1001234",
      "reason": "proactive",
      "expires_in_s": 300,
      "items": [{"type": "text", "text": "anyone still up?"}]
    }
  ],
  "next_wait_s": 25
}
```

`items` имеет ту же форму, что и `replies`. `reason` — это `proactive`, `follow_up` или `excuse`, а `conversation_type` — `group` или `dm`. `conversation_key` — ключ, под которым агент хранит разговор, например `private:telegram:42` для личного сообщения. `conversation_id` — исходный идентификатор из события, в личном сообщении это идентификатор пользователя. Агент запоминает `reply_handle`, `connector_id` и `capabilities` из последнего принятого события в каждом разговоре, поэтому разговор становится доступным после первого сообщения.

Сообщайте о каждой доставке в `acks` при следующем опросе:

| `status` | Значение |
|---|---|
| `sent` | Все элементы отправлены. |
| `partial` | Отправлены первые `sent_items` элементов. |
| `failed` | Ничего не отправлено. |
| `expired` | Отправка не началась в пределах `expires_in_s`. |
| `refused` | Коннектор больше не разрешает этот разговор. |
| `unsupported` | Платформа не может отправлять в этот разговор без запроса. |

Правила:

- **Не более одного раза.** Агент выдаёт доставку один раз и больше никогда, что бы ни случилось с подтверждением. Храните последние несколько сотен `delivery_id` и никогда не отправляйте один дважды.
- **По порядку.** Отправляйте доставки одного разговора в порядке получения. Разные разговоры могут идти параллельно.
- **Считаются только подтверждённые доставки.** Агент считает неподтверждённую доставку неотправленной и записывает как отправленные только подтверждённые. Он ждёт подтверждения до вашего следующего опроса и не дольше `expires_in_s` плюс 60 секунд после выдачи. Закончите отправку пакета, прежде чем опрашивать снова.
- **Подтверждение активности.** Коннектор, который не выполнял опрос 90 секунд, считается отключившимся. Для его разговоров ничего не ставится в очередь, пока он не опросит снова, а то, что было в очереди для него или выдано ему без подтверждения, завершается как неотправленное. Опрашивайте снова сразу после доставки пакета. Этот опрос также несёт подтверждения пакета.
- **`unsupported` сохраняется.** После такого подтверждения агент прекращает ставить в очередь для этого разговора, пока событие не принесёт другой `reply_handle`.
- **Виды тела.** Подпись не покрывает путь URL. Поэтому агент отклоняет тело события на конечной точке исходящей очереди и тело `outbox.pull` на конечной точке событий с кодом `400` и `invalid_schema`. Событие может содержать `"kind": "event"`. Событие с любым другим `kind` отклоняется.

404 без `code` означает, что агент не обслуживает исходящую очередь. `404` с кодом `outbox_disabled` означает, что оператор отключил её через `CONNECTOR_OUTBOX_ENABLED`. В обоих случаях увеличьте интервал перед следующим опросом.

## Заговорить первым без исходящей очереди

Коннектор, который не может опрашивать, всё равно может начать личный разговор. Его собственный планировщик, например задача плагина AstrBot или запись cron, отправляет на `/v1/events` обычное событие личного сообщения с `"proactive": true`. Агент читает текст как подсказку персоне («молчит уже день; экзамен был сегодня утром»), обрезает его до 500 символов и никогда не сохраняет как слова человека. Ход по-прежнему определяют инструкции движка для инициативных сообщений, и они могут предписать персоне промолчать. Если персона заговорит, ответ вернётся в HTTP-ответе, а планировщик передаст его.

Событию нужно всё, что есть в обычных событиях коннектора: подписанные заголовки, все обязательные поля, те же `platform` и исходный `sender_id`, что коннектор отправляет для этого человека, непустой текст и каждый раз новый `message_id`. Событие с повторяющимся `message_id` молча отбрасывается. Подсказка учитывается в том же интервале для личных сообщений, что и собственные начала разговора агента (`PROACTIVE_DM_COOLDOWN_S`), и не считается активностью человека.

Всегда задавайте этот флаг; без него агент сохранит подсказку как слова человека. Групповое событие с флагом забирается (`owned: true`, чтобы коннектор не давал своему боту отвечать) и отбрасывается без чтения.

## Возможности и что теряется без них

| Чего нет | Что происходит |
|---|---|
| `outbox` | Нет запланированных начал разговора, уточняющего вопроса и резервного ответа при сбое вызова модели в группе. Идентификаторы QQ всё равно получают их через NapCat, когда `QQ_ONEBOT_URL` задан и доступен. Резервный ответ в личных сообщениях возвращается в `replies` ответа и не требует исходящей очереди. |
| `quote_text` | Агент понимает цитируемое сообщение, только если сам его видел. |
| `reply_handle` | То же, что и без `outbox`. |
| неверный `addressed` | Персона считает адресованные ей сообщения фоновым разговором. |

## Как написать коннектор

1. Получите сообщение от платформы. Пропускайте собственные сообщения бота и события, которые не являются сообщениями (вступления, отзывы сообщений, толчки).
2. Соберите описанное выше событие. Задайте `addressed` по правилам упоминаний и ответов самой платформы.
3. Подпишите и отправьте событие. Отправляйте `replies` по порядку, а когда `owned` истинно, не давайте другой логике бота говорить.
4. Если платформа может отправлять без запроса, добавьте `connector_id`, `reply_handle` и `capabilities: ["outbox"]`, а затем запустите цикл опроса: опросите, доставьте каждую доставку через её `reply_handle` и подтвердите при следующем опросе.

`integrations/sdk/personagent_connector.py` выполняет шаги 3 и 4.
